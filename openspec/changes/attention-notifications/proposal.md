## Why

During live workshops the trainer (host) and the participants lose each other's attention constantly: after sending people into a breakout/individual exercise the host has no reliable way to call everyone back if their session tab is backgrounded, and a participant who is stuck or done has no low-friction way to signal the host without unmuting or interrupting. This change adds a **bidirectional attention channel**:

- **Direction A — Host → all participants:** the host fires an OS-level notification (with sound) that surfaces on every participant's device even when the session tab is backgrounded, so "we're resuming" actually reaches a distracted, tired audience.
- **Direction B — Participant → host "bell":** a participant taps a bell in the reaction bar; the daemon logs who rang and forwards it to the always-running macOS overlay app, which plays a sound and shows a persistent card on the trainer's screen — reaching the host even while PowerPoint is fullscreen.

Both directions ride existing transport (the generic Railway `broadcast` relay and the local `ws://127.0.0.1:8765` addons bridge), so **no Railway redeploy is needed** — daemon + static changes hot-deploy on push. The overlay half of Direction B lives in the `victor-macos-addons` repo (change `bell-overlay-card`); the two are linked by the shared `bell_ring` WebSocket contract documented identically in both proposals.

## What Changes

### Master enable-gate — host turns the WHOLE capability ON/OFF, default OFF
The entire attention channel — **both** directions (host→participant OS notifications **and** participant→host bell) — is gated behind a single host-controlled, session-wide flag. Nothing is exposed to participants until the host explicitly enables it, and every session starts disabled.
- **New flag `attention_enabled` on `participant_state`** (`daemon/participant/state.py`), mirroring the existing `emoji_global_enabled` master switch — **except it defaults to OFF** (`self.attention_enabled: bool = False`) and is re-initialised to OFF on every session (re)start in `participant_state.reset()` (called from the fresh-session path `daemon/__main__.py:1228`). So no session ever starts with the bell / notification surface exposed. Persisted, restored, and surfaced exactly where `emoji_global_enabled` is (`sync_from_restore`, `snapshot`).
- **Host UI toggle** — a `#attention-master-badge` (🔔) in the host footer (`static/host.html` / `static/host.js`), mirroring the `#emoji-master-badge` control (`static/host.html:342`), POSTs to a new `POST /api/{session_id}/host/attention/global-toggle` endpoint that flips the flag, persists it, and returns the new state.
- **Live broadcast to participants** — unlike the emoji switch (which is host-only), flipping this flag `broadcast()`s a new `AttentionEnabledMsg{type:"attention_enabled", enabled}` to every participant. `_handleWsMessage` (`static/participant.html`) shows/hides the bell button **and** the notification-permission indicator the instant the host toggles — no reload. The flag also rides the participant state snapshot (`GET /api/participant/state`, `daemon/participant/router.py:696`) so a freshly joined / reconnecting participant renders the correct surface immediately.
- **Daemon-side enforcement (defense in depth, not just UI hiding)** — the participant bell endpoint (`daemon/bell/router.py`) and the host-notification broadcast endpoint both check `attention_enabled` and reject/refuse when OFF, so hitting the endpoints directly does nothing while the feature is disabled. The permission-request affordance (`Notification.requestPermission()`) is presented only when the feature is enabled.

### Direction A — Host notification broadcast (entirely in training-assistant)
- **Host control UI (phase 1).** Add a text input + "Send" button on the host page (`static/host.html` / `static/host.js`) that POSTs to a new host endpoint. Broadcasts to **all** participants; individual targeting is explicitly a later stage.
- **Delivery message (phase 1).** Add `HostNotificationMsg{type:"host_notification", text, at}` to the `PARTICIPANT_MESSAGES` registry (`daemon/ws_messages.py`). A new host endpoint calls `broadcast(HostNotificationMsg(...))` (`daemon/ws_publish.py`) — rides the generic Railway `broadcast` envelope, no Railway deploy.
- **Participant pinned permission indicator (phase 1).** A fixed, always-visible bottom element in `static/participant.html` shows whether OS notifications are granted; clicking it calls `Notification.requestPermission()` **on the user-gesture click only, never on load**. Mirrors the fixed-bar CSS of `#reconnect-giveup` or appends into the `#floating-reactions` stack. All net-new — there is no existing `Notification` code. **Gated:** the indicator is hidden/inactive (and never prompts for permission) unless `attention_enabled` is on.
- **Participant receipt (phase 1).** Add `case 'host_notification':` in `_handleWsMessage` (`static/participant.html`) → `new Notification(text)` + play a sound. **Fallback to an in-page toast + sound when permission is not granted.**

### Direction B — Participant → host bell (training-assistant side of a two-repo feature)
- **Participant bell button (phase 1).** Add a bell button to the reaction-bar container `#emoji-main-bar` (`static/participant.html`), wired like the emoji buttons. New `ringBell()` mirrors `sendEmoji` → `POST /{sessionId}/api/participant/bell` with header `X-Participant-ID` (no body — the daemon resolves the name). Light client-side throttle like the emoji path. **Gated:** the button is absent from the reaction bar unless `attention_enabled` is on, and the daemon endpoint rejects a ring when the flag is off.
- **Daemon bell router (phase 1).** New `daemon/bell/router.py` with `APIRouter(prefix="/api/participant/bell")`, mounted in `daemon/host_server.py` next to the emoji routers — forwarded automatically by Railway's catch-all proxy. It: (0) **rejects the ring when `attention_enabled` is off** — the daemon enforces the gate regardless of what the UI shows (mirrors the emoji router's `if not participant_state.emoji_global_enabled:` short-circuit at `daemon/emoji/router.py:70`); (1) resolves `caller = participant_state.participant_names.get(pid, pid)`; (2) **LOGS who + when** via `daemon_log.info("addons   ", f"🔔 {caller!r} rang the bell")`, reusing the emoji-logging idiom (timestamp auto-prefixed by `daemon/log.py`); (3) forwards to the overlay via a new `send_bell(caller_name)` in `daemon/addon_bridge_client.py` emitting `{"type":"bell_ring","caller":name}` on the 8765 bridge; (4) documents the new message in `docs/addons-ws.yaml`. Optionally also `notify_host(...)` so the host browser page renders it too, mirroring the dual-render emoji design.

## Capabilities

### New Capabilities
- `attention-enable-gate`: The host-controlled master switch that turns the whole attention capability (both directions) on/off. Default OFF, reset OFF every session; the `attention_enabled` flag on `participant_state`; the host `#attention-master-badge` toggle + `POST /api/{session_id}/host/attention/global-toggle` endpoint; the live `AttentionEnabledMsg` broadcast to participants; the flag on the participant state snapshot; and the daemon-side enforcement that the bell endpoint rejects and the host-notification broadcast refuses while the flag is off. Mirrors the `emoji_global_enabled` pattern but defaults off and is broadcast to participants.
- `host-notification-broadcast`: Host → all participants OS-level notification with sound — host Send control, the daemon host endpoint, the `HostNotificationMsg` broadcast message, and the participant receipt (`new Notification` + sound, with an in-page toast + sound fallback when permission is not granted). Refused daemon-side when the master gate is off.
- `participant-notification-permission`: The pinned, always-visible participant permission indicator that reflects OS-notification grant state and requests permission **only on a user-gesture click** (with an `<audio>` unlock during that same gesture to make later background sound reliable). Shown/active only while the master gate is on.
- `participant-host-bell`: The participant bell button + `ringBell()` throttle, and the `daemon/bell/router.py` endpoint that resolves the caller's name, logs who + when, and forwards `bell_ring` to the overlay via `send_bell` (plus optional host-browser render). The button appears only while the master gate is on, and the endpoint rejects rings while it is off.

### Modified Capabilities
- `addon-overlay-ws-bridge`: Add the new daemon → overlay `bell_ring` message to the existing addons bridge protocol (the `send_bell` sender on `AddonBridgeClient` and the `docs/addons-ws.yaml` entry). This is the training-assistant side of the shared contract; the overlay side lives in `victor-macos-addons` change `bell-overlay-card`.

## Impact

- **Master gate (`daemon/` + `static/`):** new `attention_enabled: bool = False` flag on `ParticipantState` (`daemon/participant/state.py`, next to `emoji_global_enabled` at :47), reset to `False` in `reset()` (:164 region) and carried through `sync_from_restore`/`snapshot` (:129-130, :146); surfaced on `HostStateResponse` (`daemon/host_state_router.py:90`) and in the host state message (:276); a new host toggle endpoint `POST /api/{session_id}/host/attention/global-toggle` returning `AttentionGlobalStateResponse` (mirroring `daemon/emoji/router.py:106-122`) that also `broadcast()`s an `AttentionEnabledMsg`; new `AttentionEnabledMsg{type:"attention_enabled", enabled}` in `daemon/ws_messages.py` + registration in `PARTICIPANT_MESSAGES` (:323); the flag added to the participant state payload in `get_participant_state` (`daemon/participant/router.py:714-770`); host badge `#attention-master-badge` (🔔) + `toggleAttentionGlobal()`/`applyAttentionMasterBadge()` in `static/host.html`/`static/host.js` (mirroring `#emoji-master-badge`/`toggleEmojiGlobal`); participant `case 'attention_enabled':` in `_handleWsMessage` that shows/hides the bell button and permission indicator.
- **Backend (`daemon/`):** new `daemon/bell/router.py` (`/api/participant/bell`), mounted in `daemon/host_server.py` next to the emoji routers (~`app.include_router(emoji_participant_router)`), gated on `attention_enabled`; new `HostNotificationMsg` in `daemon/ws_messages.py` + registration in `PARTICIPANT_MESSAGES`; a new host endpoint that calls `broadcast(...)` (`daemon/ws_publish.py`), refused when `attention_enabled` is off; a new `send_bell(caller_name)` method + module-level wrapper in `daemon/addon_bridge_client.py` (next to `send_emoji`); name resolution via `participant_state.participant_names` (`daemon/participant/state.py`); logging via `daemon/log.py`.
- **Frontend (`static/`):** `static/participant.html` — pinned permission indicator (fixed bar like `#reconnect-giveup` or appended to `#floating-reactions`), bell button in `#emoji-main-bar`, `ringBell()` mirroring `sendEmoji`, and the `case 'host_notification':` receipt in `_handleWsMessage` with a sound + in-page toast fallback — all gated on the broadcast `attention_enabled` flag; `static/host.html` / `static/host.js` — the notification text input + Send button, and the `#attention-master-badge` master toggle.
- **Docs:** `docs/addons-ws.yaml` gains the `bell_ring` subscribe message; regenerate `docs/openapi.yaml` and then `API.md` via `python3 scripts/generate_apis_md.py --output API.md` (never hand-edit `API.md`); record in `backlog.md`.
- **Cross-repo:** the overlay behaviour (sound + persistent bottom-left card "🔔 [Name] is calling you") is implemented in `victor-macos-addons` change `bell-overlay-card`; both proposals document the `bell_ring` contract identically.
- **Cross-change dependency:** the bell card shows the caller's **real name**, which depends on the `participant-real-names` change. Until real names exist, `send_bell` forwards whatever name the participant currently has (fictional/assigned).
- **No Railway deploy:** new participant message types ride the generic `broadcast` envelope and new `/api/participant/*` endpoints ride the catch-all proxy; both hot-deploy via the daemon on push to `master`.

## Non-Goals

- **No web-push / service worker.** Participants keep the session tab open (backgrounded) during breakouts, so a normal page `Notification` suffices. Tab-closed delivery would require web-push + a service worker — a much bigger lift, called out as an explicit future option, not part of this change.
- **No individual targeting** of host notifications — broadcast to all in phase 1; targeting a single participant is a later stage.
- **No structured event log / DB** for bell events — "who rang" goes to `logs/daemon.log`, matching the emoji precedent; there is no new persistence.
- **No per-participant enablement.** The master gate is a single session-wide flag (like `emoji_global_enabled`); the host cannot enable the feature for a subset of participants. (Per-participant targeting of host notifications is separately a later stage, above.)
- **No Swift overlay change.** The overlay side (`victor-macos-addons`, already merged) needs no rework for the gate: when the feature is disabled the daemon simply never sends `bell_ring`, so the overlay is inherently inert. Do not re-touch the addons repo for this.
